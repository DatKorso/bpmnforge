# Локальная проверка выпуска 0.1.0

GitHub CI пока не используется. Все команды выполняются в чистой публичной копии. Не публикуйте рабочий каталог с внутренними материалами или его исходную Git-историю.

## Проверка исходников

Проверьте `git status --short`, тег и версию пакета (`0.1.0`). На **каждой** версии Node.js 24 и 26 выполните:

```sh
node --version
npm ci
npx playwright install chromium
npm test
npm audit
npm pack --dry-run
```

`npm test` включает сборку, TypeScript, unit-проверки, полный набор браузерных проверок и настоящую установку архива в пустой проект с пробелами/кириллицей. Для установленного Chrome допустим `BPMNFORGE_BROWSER_CHANNEL=chrome`; основная приёмка использует Chromium Playwright. Установка зависимостей и браузера требует сети или кеша; сборка и генерация после установки не требуют сети.

Проверьте оба размера, 1440×900 и 1920×1080: `file://` offline, этапы, подробности, клавиатура, панорама, масштаб, сетка, вызов общего процесса. Автоматические проверки также сверяют геометрию HTML/BPMN, текст как данные, запрещённые URL, `RESERVED_ID`, сохранность прежних результатов, повторяемость сборки и видимый логотип. В HTML раскройте лицензии: весь текст уведомлений должен быть доступен без выхода за экран.

## Пакет

```sh
npm pack
mkdir -p "/tmp/BPMN Forge проверка выпуска"
cd "/tmp/BPMN Forge проверка выпуска"
printf '%s\n' '{"name":"bpmnforge-release-check","version":"1.0.0","private":true}' > package.json
npm install "/абсолютный/путь/bpmnforge/bpmnforge-0.1.0.tgz"
npx --no-install bpmnforge version
```

Затем скопируйте минимальный JSON из README и выполните `validate --json` и `build`. Проверьте HTML и BPMN; ошибочный JSON не должен заменить результат. Архив должен содержать LICENSE, README, руководства, CHANGELOG, schema, compiled ESM, viewer и `assets/THIRD-PARTY-NOTICES.txt`. `node_modules`, тестовые модели и приватные материалы в него не входят.

## Чистая история и тег

До очистки сохраните полный локальный Git и исходные материалы вне публичного каталога. Очищайте **отдельную копию** через `git-filter-repo`; исключайте приватные каталоги, исходные примеры, конвертер и все исторические версии зависимых документов/тестов. Перенесите текущие безопасные версии тестов/инструкций отдельным коммитом. Сохраните очищенную историю разработки кода. Проверьте все ветки и теги, сообщения коммитов, имена путей и все достижимые Git-блобы, а не только HEAD. Удалите приватные remotes и лишние refs. `git fsck --full` должен пройти.

После проверки создайте только публичный тег `v0.1.0`, соберите `bpmnforge-0.1.0.tgz` из чистого checkout этого тега и запишите SHA-256 архива. Проверьте содержимое `tar -tzf bpmnforge-0.1.0.tgz`, список refs и чистое состояние Git. Сохраните локально отчёт с версиями Node/npm/браузера, результатами тестов, audit, проверкой истории и хешем пакета.

## Публикация на GitHub

Публичный репозиторий: https://github.com/DatKorso/bpmnforge. Для публикации используйте очищенную копию с проверенными веткой/тегом. Первоначальное создание репозитория выполняется отдельно; в следующем сценарии origin уже указывает на этот адрес.

Перед созданием релиза сохраните SHA-256 пакета в `SHA256SUMS.txt` и подготовьте описание в файле `release-notes.md`. После локальных проверок:

```sh
gh auth status
git push origin main
git push origin refs/tags/v0.1.0
gh release create v0.1.0 bpmnforge-0.1.0.tgz SHA256SUMS.txt --verify-tag --title "BPMN Forge 0.1.0" --notes-file release-notes.md --latest
```

Проверьте страницу релиза, скачайте пакет, сверьте SHA-256 и установите его в отдельный проект. README содержит прямую ссылку для установки из GitHub Release. Опубликованный тег и архив закрепляют конкретную версию; для последующих изменений выпускайте новую версию.

Публикация в реестр npm, GitHub Actions, новые бизнес-примеры и заявление о поддержке Windows остаются отдельными задачами.
