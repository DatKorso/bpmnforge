# Руководство пользователя BPMN Forge 0.2.0

## Команды и файлы

После установки локального `.tgz` используйте `npx --no-install bpmnforge`; из каталога исходников — `node bin/bpmnforge.mjs`. Далее `bpmnforge` обозначает установленную команду.

```sh
bpmnforge version
bpmnforge validate "процессы/тест.bpmnforge.json" --json
bpmnforge build "процессы/тест.bpmnforge.json"
mkdir -p "Готовые схемы"
bpmnforge build "процессы/тест.bpmnforge.json" --html "Готовые схемы/тест.html" --bpmn "Готовые схемы/тест.bpmn" --json
```

CLI работает из произвольного каталога; заключайте пути с пробелами в кавычки. Относительные пути аргументов разрешаются от текущего рабочего каталога. По умолчанию заменяется **последнее расширение** исходника: `тест.bpmnforge.json` → `тест.bpmnforge.html` и `тест.bpmnforge.bpmn`, `тест.json` → `тест.html` и `тест.bpmn`. Без расширения добавляются `.html` и `.bpmn`.

`--html` и `--bpmn` независимо переопределяют выходы у обеих команд. Родительские каталоги должны существовать. Исходник, HTML и BPMN должны быть разными обычными файлами; алиасы через symlink/hardlink отклоняются. `version` не принимает дополнительные параметры. Повторные и неизвестные флаги — ошибка.

`validate` проверяет структуру, BPMN-связи, ссылки и раскладку, но не создаёт файлы. `build` сначала выполняет те же проверки, затем создаёт оба результата. Ошибка проверки не заменяет прежние результаты; при перехваченной ошибке записи генератор восстанавливает их. Аварийное завершение ОС/питания не гарантирует транзакцию двух файлов; при `PUBLISH_ROLLBACK` сохраните соседние `.bak-*` для восстановления.

## Диагностика

Без `--json` сообщение об успехе идёт в stdout, предупреждения и ошибки — в stderr. С `--json` stdout содержит один JSON-объект:

```json
{"status":"error","command":"validate","code":1,"diagnostics":[{"code":"RESERVED_ID","id":"constructor","message":"ID conflicts with an Object.prototype property","severity":"error"}]}
```

Успех содержит `status: "ok"`, `command`, `diagnostics`, `geometry`, `readability` и абсолютные пути `outputs.html`/`outputs.bpmn`. Сохраняйте `code` и `id` при обсуждении ошибок; текст сообщения может меняться. Геометрические диагностики могут включать `relatedIds`, `point` и `bounds`.

| Код завершения | Значение |
| --- | --- |
| 0 | Проверка или сборка успешна; предупреждения допустимы |
| 1 | Ошибка JSON, структуры, BPMN-правил или геометрии |
| 2 | Неверные аргументы, пути или ошибка доступа/записи |
| 3 | Внутренняя ошибка генератора или сбой восстановления |

`MISSING_DOCUMENT` — предупреждение: относительный файл не найден возле выходного HTML. В viewer такая ссылка помечается как недоступная. `ACCEPTED_CROSSING` — информационная диагностика проверенного прямоугольного пересечения; HTML показывает мостик, BPMN сохраняет исходные точки маршрута.

## Формат и поддерживаемый BPMN

Начните с JSON в [README](../README.md), затем сверяйтесь со [схемой](../schema/bpmnforge.schema.json). Все ID глобально уникальны, начинаются с латинской буквы или `_`, далее допускаются латинские буквы, цифры, `_`, `.` и `-`; длина до 100 символов. Префикс `BPMNFORGE_` зарезервирован схемой, свойства `Object.prototype` (`constructor`, `__proto__`, `toString` и другие) дают `RESERVED_ID`.

`stages` задают порядок этапов чтения, `processes` — процессы, `pools` — участников (ровно один пул на процесс), `lanes` — дорожки, `nodes` — блоки, `flows` — связи. Блок указывает `process` и `stage`; если у процесса есть дорожки, обязателен `lane` этого процесса. `description` — обычный многострочный текст, `links` — массив `{ "name", "href" }`.

| Конструкция | Поле/правило |
| --- | --- |
| Начало / конец | `start`, `end`; у начала нет входящих, у конца нет исходящих sequence |
| Задачи | `task`, `userTask`, `serviceTask`, `sendTask`, `receiveTask`, `businessRuleTask` |
| XOR | `xor`; исходящие варианты содержат `condition` или указаны как `defaultFlow` шлюза; у default нет condition |
| AND | `and`; без условий и default |
| Вызов | `callActivity` с `calledElement`: ID локального процесса; рекурсия/циклы вызовов запрещены |
| Таймер | `timerCatch` с `timer: { "kind": "timeDuration", "expression": "PT1H" }`; также `timeDate`, `timeCycle` |
| Событийный подпроцесс | `eventSubProcess`; один уровень, дети указывают `parent`; начало `conditionalStart` с `condition`, конец `end` или `terminateEnd` |
| Sequence | `type: "sequence"`; концы — узлы одного процесса и одного контейнера; возвраты явно `return: true` |
| Message | `type: "message"`; разные участники, допустимые задачи/направленные события или пулы; не шлюзы |
| Annotation | `annotations` с `text`; `association` связывает заметку и узел одного процесса |

Процесс без `external: true` требует начала, конца и достижимости обязательных узлов. `required: false` исключает узел из проверки достижимости. Внешний процесс может быть пустым. Условное начало разрешено только внутри событийного подпроцесса; сам подпроцесс не соединяется sequence со внешними узлами. `originalType` у association предназначен для явного сохранения происхождения информационной связи; не используйте его для обхода ошибок message flow.

Генератор экспортирует читаемые неисполняемые BPMN-процессы (`isExecutable: false`). Выражения условий и таймеров сохраняются как данные; их прикладной смысл и корректность бизнес-правил проверяет автор. Импорт BPMN, произвольные типы событий, обычные/глубоко вложенные подпроцессы и редактирование схемы в браузере не поддерживаются.

Лимиты: исходник до 4 MiB, до 500 узлов, 1000 связей, 100 этапов, 50 процессов/пулов, 200 дорожек/заметок. Другие лимиты строк и координат указаны в схеме.

## Раскладка и чтение

Опция `--layout auto|grid|graph` одинакова у `validate` и `build`; по умолчанию используется `auto`:

- `auto` сохраняет полную ручную геометрию. При наличии `column` или `row` выбирается сетка, иначе — граф.
- `grid` сохраняет логические `column`/`row`, порядок и явно пропущенные ячейки внутри этапов и дорожек. Расстояния вычисляются по содержимому; прежние абсолютные координаты не воспроизводятся.
- `graph` вычисляет уровни по sequence без `return: true`, группирует альтернативы и использует длинную последовательность как визуальную ось. Это не объявление главного бизнес-сценария. `column`/`row` пересчитываются только в памяти, исходный JSON не меняется. Message и association не определяют порядок шагов.

Выбор рядов в `graph` эвристический: учитываются размещённые предшественники той же дорожки и этапа, затем длина оставшегося sequence-продолжения, включая следующие этапы. Предшественник из другой дорожки не задаёт предпочтительный ряд. Поэтому короткая ветвь может оказаться ниже длинной, даже если их перестановка уменьшила бы пересечения. Проходы улучшения маршрутов не переставляют блоки; глобальный минимум пересечений не гарантируется. Для сохранения авторских `column`/`row` выбирайте `grid`, для точного расположения — `bounds`.

```sh
bpmnforge validate source.json --layout graph --json
bpmnforge build source.json --layout graph --json
bpmnforge build source.json --layout grid --html grid.html --bpmn grid.bpmn --json
```

`BuildOptions.layout` и второй аргумент `layoutProcess(model, { layout: 'graph' })` принимают те же режимы. Формат JSON остаётся `version: 1`. Геометрия автоматически размещённых схем использует общий профиль `readable-v1`: задачи имеют ширину 200, 240 или 280 и высоту, кратную 40, с полями минимум 16; центры сохраняют сетку 20. Генератор и viewer используют общие детерминированные метрики шрифта и перенос длинных идентификаторов. Каждая колонка получает свой интервал; широкая задача больше не увеличивает шаг всего этапа. Пустая колонка `grid` сохраняет 80 единиц интервала; коридоры могут потребовать расширения.

| Правило профиля | Значение в координатах схемы |
| --- | --- |
| Между границами соседних шагов | Предпочтительно 80, минимум 40 |
| Между занятыми областями рядов, включая подписи | Минимум 40 |
| Независимые параллельные линии / маршрут и чужая фигура | Минимум 14 |
| Подпись и чужое содержимое | Минимум 8 |
| Прямой подход к порту | Предпочтительно 20–40; короткая прямая связь допустима |
| Поля содержимого дорожки | Минимум 40 |

Это правила BPMN Forge, а не численные требования BPMN. [OMG BPMN 2.0.2, §10.6.1](https://www.omg.org/spec/BPMN/2.0.2/PDF#page=318) допускает подключение к грани шлюза. Forge сначала совместно распределяет входы и выходы по четырём вершинам с учётом ручных портов. Степень больше четырёх или препятствия фиксированной геометрии могут потребовать бокового порта; `READABILITY_GATEWAY_PORT_EXCEPTION` объясняет исключение. Сам шлюз и правила процесса не меняются. Общие рекомендации по композиции: [примеры Camunda](https://camunda.com/bpmn/examples/) и [соглашения SAP Signavio](https://help.sap.com/docs/signavio-process-manager/workspace-admin-guide/modeling-convention-rules-for-bpmn-2-0).

Для автоматически размещённых дорожек генератор выбирает соседство по sequence-переходам, отдавая приоритет входу и непосредственному следующему шагу. Это помогает читать переходы между исполнителями без высокой пустой полосы промежуточной дорожки. Принадлежность узлов дорожкам и порядок в исходном JSON сохраняются; фиксированные `bounds` сохраняют авторское расположение.

Маршруты сначала проходят обязательные проверки, затем сравниваются по оценке «длина + 40 × изгибы + 400 × пересечения» со штрафом за смещение порта задачи от середины стороны. После первого допустимого решения выполняется не более двух проходов улучшения, с суммарным ростом длины не более 5% и размеров не более 10%. Эти пределы не препятствуют первоначальному обязательному устранению коллизий. Поиск детерминирован и ограничен; сложная фиксированная геометрия может потребовать согласованных подсказок.

`bounds`, `labelBounds` и `route` имеют приоритет над профилем. Полная ручная геометрия включает узлы, заметки, пулы и дорожки. `route` — ортогональная ломаная от контура источника до контура цели, не пересекающая чужие фигуры и подписи. Маршруты сохраняются буквально. Наложения фигур и недопустимые маршруты дают ошибки. Отклонения интервалов, близкие параллельные линии, удалённые подписи и тесно расположенные стрелки/мостики дают рекомендации, которые сами по себе не меняют успешный код завершения.

`readability` содержит фактически выбранный `layout` (`manual`, `grid` или `graph`), число и плотность пересечений, минимальный параллельный зазор, пары близких участков, зоны разведения общих портов, длины и изгибы каждого маршрута, суммарную/медианную/максимальную длину, размещение подписей и зазоры декораций. Рекомендуемый минимум для независимых параллельных участков — 14 единиц координат; подключения в зоне общего узла учитываются отдельно. `MANUAL_ROUTE_CLEARANCE` предупреждает о близком ручном маршруте, сохраняя его. Другие рекомендации имеют префикс `READABILITY_`; разбирайте их по `id`, `relatedIds` и координатам. Сравнивайте grid и graph по всем показателям: уменьшение пересечений может сопровождаться ростом длины или числа изгибов.

`readability` сохраняет прежние поля и добавляет `profile: "readable-v1"`, `intervalDeviations`, `portExceptions`, `shapeClearances`, `dimensions` и `readingFragments`. Последнее поле оценивает фрагменты при двух стандартных размерах окна и консервативном размере полотна; фактический браузерный результат проверяется отдельно. `labels[].distanceToOwner` измеряется между границами подписи и владельца, `distanceToSource` — до начала ветви.

HTML открывается через `file://` без сетевых запросов для схемы. Список входов объединяет межэтапные sequence-входы и самостоятельные start-события. Межэтапный вход выбирается первым; при отсутствии обоих используется самый левый блок. Все входы доступны в выборе. «Читать фрагмент» сначала включает непосредственный следующий шаг, затем ближайшую развилку и соседей глубиной до двух переходов. Масштаб 100–125% сохраняет текст от 14px и поля 32px. Если следующий шаг не помещается, кнопка «Далее» открывает его; отчёт содержит `READABILITY_FRAGMENT_CONTEXT`.

«Этап целиком» вписывает узлы и подписи этапа; удалённые обходы маршрутов не уменьшают масштаб. Полные маршруты доступны панорамированием и в обзоре, соседние этапы по умолчанию видны полностью. Приглушение включается в меню «Настройки» и сохраняется при переключении этапов до закрытия страницы. Камера, режим и выбранный вход каждого этапа сохраняются в текущей сессии; «К началу этапа» восстанавливает фрагмент выбранного входа. Названия дорожек занимают отдельную полосу 180px вне рисуемой области. Полные имена доступны при наведении и в контексте панели выбранного блока. «Вся схема» вписывает полную интерактивную схему без перекрывающих зон этапов и приглушения. Выбор блока сохраняет режим всей схемы.

Щелчок по блоку или фокус + Enter/Space открывает закрываемую панель. Переходы по входящим/исходящим связям расположены перед описанием и различаются цветом, стрелками и словами. В режиме этапа переход по связи одновременно выбирает цель и этап; явное переключение этапа очищает выбор. У вызова доступен переход к общему процессу, у событийного подпроцесса — внутренние шаги. Документы и ссылки из `links` не включаются в HTML.

Навигация «Вся схема» и этапы находятся в первой строке панели. Во второй расположены масштаб и инструменты чтения; сетка, информационные связи и приглушение вынесены в меню «Настройки».

Все связи видны первоначально. Переключатель «Информационные связи» с количеством скрывает message/association только в HTML; BPMN сохраняет все связи. Названия association рисуются отдельным HTML-слоем по рассчитанным bounds: стандартный BPMN сохраняет сами association, а их имена — в documentation, поскольку association не поддерживает атрибут name. Стандартный viewer не отображает эти имена как подписи. Неподдерживаемые поля в BPMN не добавляются.

Колесо мыши масштабирует возле курсора, перетаскивание — панорама. Кнопки `+`/`−` последовательно увеличивают/уменьшают масштаб, включая мелкий обзор. Изменение размеров окна и панелей сохраняет центр и масштаб. После фокуса на полотне стрелки перемещают схему, `+`/`−` масштабируют, `0` сбрасывает текущий вид. «Сетка» включается мышью или Space и не меняет экспорт.

## Текст, документы и лицензии

Текст и подписи экранируются; HTML/JavaScript в описании не исполняется. Разрешены HTTPS-ссылки без учётных данных и безопасные относительные пути. `javascript:`, `data:`, `file:`, абсолютные пути, `..`, управляющие символы и обратные слеши отклоняются. Относительные ссылки в JSON разрешаются **от выходного HTML**, это используется при проверке доступности документов в CLI. Содержимое `links`, включая названия и адреса, остаётся только в исходном JSON и не передаётся с HTML. Адреса, вручную написанные в описаниях, автоматически не удаляются.

Лицензии компонентов находятся в HTML и пакете. Логотип bpmn.io должен оставаться полностью видимым согласно лицензии viewer. Лицензия собственного кода — [MIT](../LICENSE).
